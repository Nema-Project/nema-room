# 本机桌面迁移计划

日期：2026-10-24。依据：[首版范围](../specs/2026-10-24-local-desktop-first.md)。以下为待完成工作，不代表桌面实现已经存在。

> 此文件为最初迁移路线。用户已进一步确认保留本机 Web、优先 Windows/macOS、采用复用优先方案及未签名预发布。执行时使用[详细实施计划](2026-10-24-desktop-implementation.md)及其[已确认设计](../specs/2026-10-24-desktop-packaging-design.md)，不要重复执行本文件中的概要步骤。

## 1. 验证技术路径

- 盘点界面、hub、daemon、CLI / MCP / hook 的依赖和入口。
- 用现有界面和真实任务链验证桌面打包路径，再确定框架；不只做展示网页的窗口。
- 审计 SQL、事务、队列锁与迁移机制，验证候选嵌入式存储的磁盘持久化、退出重开与中断恢复，再确定引擎。
- 记录已验证、存在限制和未验证项。不把新增服务器功能纳入本轮选型要求。

## 2. 跑通最小本机闭环

- 桌面启动自动准备数据目录、数据库迁移、Room 服务和任务执行器。
- 创建 workspace → 发送消息 → 模型调用 → 知识更新 → 展示回复与 Git 历史。
- 退出重开后恢复同一批消息、条目和设置；中断任务有明确状态。
- 不启动 Docker、不配置 Nema 服务器，本体不借用开发机全局 Node/npm。

## 3. 迁移既有能力

- 接回模型模式、凭证保护、插件、仓库绑定、开发包、CLI / MCP 和上报 hook。
- 明确窗口关闭与应用退出的行为，以及外部工具找不到后台时的提示或暂存行为。
- 验证单实例或互斥策略，避免同时写同一套数据、抢占任务或刷新同一凭证。
- 提供旧数据迁移路径，使用副本校验并保留原数据及回退方式。

## 4. 桌面发布验收

- Windows、macOS、Linux 安装包、首次启动、退出、升级与重启验证。
- 真实模型下完成讨论、追问、历史和开发交接；检查断网错误及明确重试。
- 更新三语言安装说明与 CI。桌面首版不再以 Compose 冒烟作为产品交付验收。
- 备份功能、多设备同步、团队只读、远端账户与部署留在后续范围。
