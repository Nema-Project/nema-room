# BYOK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `authMode=byok` 时，`codex-direct` 用 `~/.nema/byok-key` 调用配置的 Responses 地址，模型仍然只有 Room 的三个函数。

**Architecture:** 钥匙是单独的 0600 文件，不进 `auth.json`。传输层沿用现有的 `send()`，BYOK 的 profile 把 401 改成不刷新、不重试。适配器在 `byok` 分支跳过模型列表，`config.model` 必填。

**Tech Stack:** TypeScript、Node ≥ 22、现有 `TokenSource` / `TransportProfile` / Vitest。不新增依赖。

**Spec:** `docs/superpowers/specs/2026-10-23-agent-runtimes-design.md` 的 BYOK 一节，以及 `docs/superpowers/specs/2026-10-21-nema-room-design.md` 的 6.1、6.7。

## Global Constraints

- hub 不改。key 不进 hub、不进日志、不进 `task.event`。
- 适配器仍是 `codex-direct`。不启动 `claude` 或 `codex`，不走 `nema mcp`。
- 默认 `authMode` 仍是 `siwc`。`codex` / `codex-cli` 迁移结果仍是 `codex-direct` + `compat`，不会变成 `byok`。
- 文件是 `<nemaHome>/byok-key`，0600，一行。`nema auth byok` 从 stdin 读。空串或含换行则拒绝且不改已有文件。拒绝符号链接。`nema auth logout` 只删 `auth.json`。
- 不读 `OPENAI_API_KEY` 或其它环境变量。
- `byokBaseUrl` 未设置时用 `https://api.openai.com/v1`。允许 `https://` 任意主机，以及主机名恰好是 `127.0.0.1` 或 `localhost` 的 `http://`（可带端口和路径）。其它 `http://` 拒绝保存，手改进配置文件也拒绝加载。
- 请求是 `POST {baseUrl}/responses`，`Authorization: Bearer <key>`，`originator: nema-room`，`User-Agent: NemaRoom/<版本>`。不送 `ChatGPT-Account-ID`。
- 401 不刷新、不重试、不写 `auth.json`。错误文案是 `API key 被拒绝，请在终端运行 nema auth byok`，不附带响应体。网络错误和 5xx 仍重试 1 次。
- `config.model` 必填，不调用 `listModels`，不使用 `FALLBACK_MODEL`。缺模型的文案是 `BYOK 需要指定模型，请运行 nema config set model <名称>`。
- `reasoningEffort` 仍放进 Responses 请求。轮数、工具次数、10 分钟、`store: false`、三个 Room 函数与现在的直连循环相同。
- 失败不改跑 `siwc`、`compat` 或 `claude-code`。
- 单元测试不访问公网，不读真 key。

## Review Focus

1. **401 的响应体里含有 key**：错误文本仍是上面那句固定文案，`auth.json` 字节不变，`getAccessToken({ force: true })` 不被调用。→ Task 3、Task 4。
2. **手改 `byokBaseUrl` 为 `http://evil.example`**：`loadConfig` 抛错，请求发不出去。→ Task 1。
3. **环境变量 `OPENAI_API_KEY` 有值，但 `byok-key` 不存在**：任务失败，文案是缺 key，假服务收到 0 个请求。→ Task 4。
4. **SIWC 的 401 仍要刷新一次**：`refreshOn401` 缺省时现有 transport 测试继续通过。→ Task 3。
5. **`nema auth logout`**：`auth.json` 删除，`byok-key` 字节不变。→ Task 2。

### Task 3: 401 不刷新

**Files:**
- Modify: `apps/cli/src/direct/transport.ts`
- Test: `apps/cli/test/direct/transport.test.ts`

**Interfaces:**
- Consumes: `TokenSource`。
- Produces:
  - `TransportProfile.refreshOn401?: boolean` 缺省视为 `true`。
  - `export class ByokRejectedError extends Error` 消息固定为 `API key 被拒绝，请在终端运行 nema auth byok`。
  - `export const BYOK_PROFILE: TransportProfile` `baseUrl` 为 `DEFAULT_BYOK_BASE_URL`，`extraHeaders` 返回 `{}`，`refreshOn401: false`。`modelsPath` 可保留 `"/models"`，这一档不调用它。
  - `send()` 在 `refreshOn401 === false` 且状态为 401 时立刻抛 `ByokRejectedError`。不调用 `getAccessToken({ force: true })`，不调用 `recordAuthError`，不把响应体放进错误。

- [ ] **Step 1: 写失败测试**

用现有假 Responses 服务。profile 为 `BYOK_PROFILE` 且 `baseUrl` 指到假服务。假服务先回 401，响应体含 `sekret-key`，再回一条成功 SSE。Token source 的 `getAccessToken` 在 `force: true` 时抛错，`recordAuthError` 也抛错。断言抛 `ByokRejectedError`，消息恰好是那句固定文案，且不含 `sekret-key`，请求次数为 1。再加一个用例：同一 profile，先 500 再成功 SSE，请求次数为 2。现有的「401 → forced refresh once」测试不改断言。

- [ ] **Step 2: 跑测试确认失败**

Run: `npx vitest run --project @nema/cli test/direct/transport.test.ts`
Expected: FAIL，401 仍会第二次取 token。

- [ ] **Step 3: 实现 `refreshOn401` 分支、错误类和 `BYOK_PROFILE`**

### Task 4: 接到直连适配器

**Files:**
- Modify: `apps/cli/src/direct/adapter.ts`
- Test: `apps/cli/test/direct/adapter.test.ts`

**Interfaces:**
- Consumes: `ByokTokenSource`、`BYOK_PROFILE`、`DEFAULT_BYOK_BASE_URL`、`ByokRejectedError`、`normalizeByokBaseUrl` 已写入的配置。
- Produces: `CodexDirectAdapter.run` 在 `config.authMode === "byok"` 时使用 `ByokTokenSource` 和 `{ ...BYOK_PROFILE, baseUrl: config.byokBaseUrl ?? DEFAULT_BYOK_BASE_URL }`。缺 key 或没设 `model` 时在发请求前返回 `{ ok: false }`。`errorMessage` 对 `ByokRejectedError` 原样返回。

- [ ] **Step 1: 写失败测试**

假 Responses 服务加一个只回 200 的 Room hub（照现有 adapter 测试）。五个用例：

1. `authMode: "byok"`、`model: "gpt-z"`、`byokBaseUrl` 为假服务的 origin。key 文件是 `sekret-key`。假服务记录到的 `Authorization` 是 `Bearer sekret-key`，没有 `ChatGPT-Account-ID`，`originator` 是 `nema-room`，请求路径以 `/responses` 结尾。请求体的 `reasoning.effort` 是配置里的值。没有任何 `/models` 请求。
2. 没有 key 文件，`process.env.OPENAI_API_KEY` 为 `from-env`：`ok: false`，错误是缺 key 那句，请求次数为 0。
3. 有 key 但没有 `model`：错误恰好是 `BYOK 需要指定模型，请运行 nema config set model <名称>`，请求次数为 0。
4. 假服务回 401，响应体含 `sekret-key`。预先写好的 `auth.json` 字节不变。错误恰好是 `API key 被拒绝，请在终端运行 nema auth byok`，不含 `sekret-key`。请求次数为 1。
5. `authMode` 仍是 `siwc` 且没有 SIWC 登录：错误仍是现有的 `NOT_LOGGED_IN`，不读 `byok-key`。
