# 输入框 `@` 提及 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**状态：部分可实现。** D1–D9 已由用户在 2026-10-31 决定；同日 01:34 JST 重新划定范围为「工作区内的上下文」，仓库文件提及取消。**D10（tag）、D11（成员）、D12（话题）待用户决定**，涉及它们的三批在决定前不动手。

**Goal:** 在输入框里用 `@` 提及工作区里的附件、知识条目和话题。提及以结构化记录存在消息上：条目在 prompt 里内联正文，附件通过已有的投递通道真的送到 agent，话题只给标题和锚点。

**Architecture:**
- **shared：** `MessageMention` 增加 `attachment` 支、去掉 `file` 支（M0a）。
- **hub：** 新增候选路由 `mention-context`（M1）；在 `postUserMessage` 校验并保存，附件提及并入投递集合，在 `buildPrompt` 里加「本次提及的上下文」段（M2）。
- **web：** 在 `Composer` 里加行内 `@` 菜单和提及托盘（M3）。

**Tech Stack:** TypeScript、zod、Hono、Next.js、Vitest。不新增依赖，不加数据库迁移。

**Spec:** [输入框 `@` 提及上下文](../specs/2026-10-31-mentions-design.md)。下文「§n」指该 spec「设计」一节的第 n 小节。

**Issue:** [#136](https://github.com/Nema-Project/nema-room/issues/136)。范围修订记录见 [#136 评论](https://github.com/Nema-Project/nema-room/issues/136#issuecomment-6527997406)。

## Review Focus

- web 永远拿不到仓库文件，也拿不到附件以外的内容；hub 不因为提及去读仓库或文件系统。
- 提及的归属校验都在 hub 端完成：条目 id、附件 id（必须本 workspace 且 `status = attached`）、话题 id。
- 附件提及**真的进入投递集合**；超过 8 个或 32 MiB 时在发送处回 400，不静默丢弃。
- prompt 段落不改变现有各段的顺序，只在「引用的消息」和「本次用户消息」之间插入一段；条目预算按字节算。
- 旧 hub、旧 web 和新的一方搭配时，除了没有提及之外，行为与现在一样。
