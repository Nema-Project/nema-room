# 输入框 `@` 提及 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**状态：可实现。** D1–D9 已由用户在 2026-10-31 决定，全部按 #136 的推荐（见 spec 末尾「已决定的事项」），实现时不得改变这些选择。某项决定在实现中做不到时，停下报告，不要悄悄降级。

**Goal:** 在输入框里用 `@` 提及知识条目、绑定仓库里的文件和话题。提及以结构化记录存在消息上，hub 构建 prompt 时把条目正文内联，文件只给引用并固定提交号，话题只给锚点。

**Architecture:**
- **shared：** 新增 `MessageMention` 契约，并给 `UserMessageMeta` 加 `mentions`。
- **daemon：** 新增 RPC `repo.files`，列出主分支上的文件路径；`code__read` 增加可选 `ref`。
- **hub：** 新增路由模块 `mentionsApi.ts`，做文件模糊查询；在 `postUserMessage` 里校验并保存提及；在 `buildPrompt` 里加"本次提及的上下文"段。
- **web：** 在 `Composer` 里加行内 `@` 菜单和提及托盘；`Markdown` 的 MARKER 补上 `W`。

**Tech Stack:** TypeScript、zod、Hono、Next.js、Vitest。不新增依赖，不加数据库迁移。

**Spec:** [输入框 `@` 提及上下文](../specs/2026-10-31-mentions-design.md)。下文「§n」指该 spec「设计」一节的第 n 小节。

**Issue:** [#136](https://github.com/Nema-Project/nema-room/issues/136)。

**Base:** 写本计划时的 `origin/main` 是 `080e8aa`（Merge pull request #128）。动手前先执行 `git fetch origin main`，再执行：

## Global Constraints

- **目标版本：** v0.2.0。用户已接受 v0.2.0 推迟约一周。话题提及留在 v0.2.0，不顺延。
- **与 Skills 的顺序：**
  - 会改 `apps/web/components/Composer.tsx` 或 `apps/web/lib/slash.ts` 的批次（M5），**必须在 Skills S6 合并后**才能开始。
  - 同改 hub 文件的 M4 也排在 S6 之后，见「与 Skills 各批的文件核对」。
  - 不修改 [Skills 计划](2026-10-30-skills-progressive-loading.md)，其中的 `/skill-name` 由 Skills 那条线在 S6 时统一改。
- **避让：**
  - 不改 `packages/shared/src/index.ts`（Skills S0 / #133 在改）。新契约由 `workspace.ts` 转出。
  - 不改 `packages/shared/src/protocol.ts`、`apps/cli/src/daemon/setup.ts`、`apps/cli/src/direct/*`、`apps/cli/src/claude/*`、`apps/cli/src/skills/*`、附件相关文件、`apps/hub/src/wpFormat.ts`。
- **限制（`MENTION_LIMITS`）：**
  - 每条消息最多 20 个提及。
  - 条目正文每条 4096 字节，合计 16384 字节。
  - 文件候选最多 50 条；菜单每组最多 8 条。
  - 话题锚点最多 1024 字节。
  - `repo.files` 最多 50,000 条；daemon 内存缓存 8 份；每个仓库调用超时 5 秒。
- **命名：** daemon RPC 叫 `repo.files`（沿用 `repo.*` 单数命名），hub 路由是 `GET /api/workspaces/:id/mention-files?q=`。
- **兼容：**
  - 不加迁移，`mentions` 存在 `messages.meta` 里。
  - `PostMessageBody` 保持非 strict。
  - 旧 daemon 返回"未知方法"时，路由报 `unsupported`。
  - 旧 daemon 会忽略 `ref`，prompt 里已有说明。
- **测试：** 不联网，只用临时数据库、临时 git 仓库和假 daemon。每个任务只跑它列出的测试文件和 `npm run typecheck`，web 任务另外跑 web 的构建或类型检查；全量测试交给 CI。
- **文案：** 页面文字进 `apps/web/messages/{en,zh,ja}.json`，三种语言一起改。
- **提交信息：** 用英文。

## Review Focus

- web 永远拿不到文件内容。hub 不读、不存文件内容。
- 提及的归属校验都在 hub 端完成，包括 repoId、条目 id 和话题 id。
- `code__read` 的 `ref` 只能是主分支历史上的提交；其他情况退回主分支，并在结果里注明。
- prompt 段落不改变现有各段的顺序，只在"引用的消息"和"本次用户消息"之间插入一段。
- 旧 hub、旧 daemon 和新的一方搭配时，除了没有提及之外，行为与现在一样。
