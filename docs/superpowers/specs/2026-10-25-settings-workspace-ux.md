# Workspace creation and connection settings UX

User request: visible workspace creation feedback with confirm/cancel controls, dropdown-based connection selection, and understandable Agent/Provider settings. The user selected reorganizing existing connections rather than adding providers; GitHub credentials belong with the GitHub plugin.

Workspace creation is a small, fully specified change: an inline name field with accessible confirm/cancel icons; Enter confirms and Escape cancels before submission. Immediately after submission show a creating status, disable editing/actions while the request is pending, and prevent duplicate requests. Cancel means cancel the draft, not promise to undo an already submitted server operation. On failure retain the name and show a retryable error; on success select the created workspace as today. Empty/whitespace-only names cannot submit. English, Japanese and Chinese remain supported.

Connection settings follow the selected approach: distinguish the Agent/runtime, the model service and its login method. Existing modes remain exactly codex-direct/siwc, codex-direct/compat, codex-direct/byok and claude-code; no new provider transport or credential migration. Human-facing labels describe ChatGPT browser login, existing local Codex login, API-key connection, and local Claude Code. Internal SIWC/BYOK/adapter identifiers are not the primary user labels. Dropdowns show only applicable choices and subsequent fields, with a brief explanation of the selected connection. Provider settings (runtime, service, sign-in, service address, credentials) save separately from model settings. After the saved provider is connected, the model is chosen from that provider's model list. There is no custom model ID field. A saved model that is not in the current list stays stored until the user saves a listed replacement. The catalog request runs only while model settings are open for a connected codex-direct provider. Claude Code does not use that list.

Claude Code installation information belongs to the Claude Code connection. Latest user steering replaces the earlier GitHub-token-form proposal: GitHub access uses already-authenticated local `gh` commands or an existing MCP configuration. Nema must not ask users to paste or save a GitHub token. ModelSettings and PluginsPage contain no GitHub-token form. Plugin UI explains connection/tool availability; it does not promise discovery of an arbitrary MCP client's credentials. The direct `gh` integration is a separate Task8f; the existing MCP configuration source is awaiting clarification. Existing secret files/APIs are preserved for compatibility without reading or deleting real credentials. Model authentication, cancellation and explicit opt-in tests retain existing behavior. A saved model id that is still in the provider's list is selected again. An id that is not in the list is left unchanged until the user saves a listed model.

Approaches considered: cosmetic replacement of the four radios with one dropdown, or contextual Agent/service/login configuration. The contextual approach follows the user's selected organization and the Hermes/Multica reference. Workspace feedback is independent and implemented first. No new provider/runtime, updater, installation flow, or unrelated feature is part of this UX change.

Implementation remains in the existing local feature checkout and existing SDD plan. Preserve unfinished Task9a files. Use fake APIs/isolated test data; no real login, credentials, providers or default user profiles. Validate pending/error/retry states and existing configuration semantics, then inspect the actual UI and package the final combined change once.
