# Electron、本机 Web 与 tag 发布设计

日期：2026-10-24。状态：用户已于 2026-10-24 确认按本设计推进，接受未签名预发布；尚未实现。

## 意图与范围

用户优先考虑现有代码复用程度与尽快稳定交付。保留 Web 应用，Windows 与 macOS 优先提供桌面安装包；桌面入口不能使用时，仍可通过本机 `127.0.0.1` Web 入口使用基本能力。源码已采用 MIT，用户确认远程仓库已公开；版本 tag 触发 GitHub Actions，公开 Release 下载地址。

用户当前没有 Apple Developer 账号或 Windows 签名证书，已同意先交付未进行发行者身份签名、公证的预发布安装包，明确说明系统提示和首次打开方式。Apple Silicon 所需的本地技术性签名与 Developer ID 身份签名、公证不是一回事，不能把前者描述成已获 Apple 认证。

用户补充：未来可能清空源码仓库现有提交历史。当前不执行历史重置。应用版本来自显式版本字段，打包不依赖完整 Git 历史、提交数量或历史 tag；发布只依赖当前源码快照、lockfile 和本次版本 tag。发布记录中保留版本、当前提交 SHA 与产物校验值；未来重置是否保留旧 tags/Releases 届时单独处理。源码仓库历史与应用保存的聊天、知识 Git 历史是不同的数据，重置前者不应触碰后者。

首版必须在本机完成聊天、知识、历史、任务和模型执行。同步、备份功能、团队只读查看及可选服务器延期；数据持久化和升级时保护既有数据仍属基本要求。[已确认范围](2026-10-24-local-desktop-first.md)继续适用。

## 方案比较与当前选择

| 方案 | 对当前代码的影响 | 取舍 |
| --- | --- | --- |
| Electron + 共用本地核心 | 复用 React、Node.js 服务与适配器；保留 HTTP/WebSocket 边界 | 自带 Chromium/Node，体积和资源开销较大，但减少系统 WebView 差异 |
| Tauri + Node 附带程序 | 可保留业务代码，新增 Rust 外壳和平台 WebView 适配 | 外壳较轻，但多一套构建和进程管理，整体体积仍包含本地运行依赖 |
| 仅保留本机 Web | 最少窗口层工作 | 不满足优先提供 Windows/macOS 桌面安装体验的方向 |

根据用户选择的“复用程度和尽快稳定交付”，本草案采用 Electron；保留浏览器模式。electron-builder 作为打包工具是实现提议，便于在同一流水线配置 Windows/macOS 产物，不是用户指定的依赖。

## 组件与启动

```text
桌面入口 ─── Electron 窗口 ─┐
                           ├─ 同一本机 HTTP 界面与 API ─ 本机运行核心
浏览器模式入口 ─ 系统浏览器 ┘                             │
                                    聊天/任务数据库 + 知识 Git 仓库
                                                        │
                                     模型适配器、CLI/MCP、仓库工具
```

- 保留现有 React 组件、hub 业务模块、Room 校验、daemon 执行与插件。首阶段保留本机 hub ↔ daemon 协议，改由本机启动器管理，不要求用户开两个终端。以后是否合并进程由实际维护成本决定。
- 同一套核心支持桌面启动和独立浏览器启动。浏览器模式不依赖创建 Electron 窗口；打包包含其需要的 Node 运行时和启动入口，不依赖用户全局 Node/npm。
- 现有 Next.js 应用先验证 standalone 生产输出，避免为打包直接重写界面框架。不得把开发服务器当发布运行时。文件路由、静态资源、字体及运行时依赖都需进入安装包。
- 桌面与浏览器模式共用同一份本机数据。每个数据目录仅一个运行核心持有写入权；第二个入口连接已运行实例，不启动第二个数据库或重复领取任务。锁失效后的恢复检查必须避免误杀其他进程。
- 关闭窗口默认只关闭界面，后台保留以支持任务与 hook；提供明确的“退出 Nema”入口。完整退出停止新任务、结束受管进程、关闭数据库；不能完成的任务标记中断，重开后明确恢复或重试。
- 开机自启动与应用自动更新首版不实现。用户手动下载安装新版本，更新后沿用数据目录。外部 hook 找不到核心时沿用安全暂存/错误提示，不静默启动一份竞争实例。

## 存储、依赖与兼容

- 首版不需要 Docker 或独立 PostgreSQL 服务。本地磁盘 PGlite 是优先验证的候选，以复用 PostgreSQL SQL 和现有 Db 接口；这不是已经验证的生产结论。
- 在正式迁移前验证：实际迁移 SQL、全文检索、事务、队列锁、磁盘持久化、崩溃重启和跨进程互斥。只允许一个数据库拥有者；不支持的 SQL/锁语义必须有明确等价实现和测试，不能靠跳过测试交付。若候选不适合，先更新设计，再切换引擎。
- 项目知识继续使用现有 Git 格式和历史。Git 是基本运行依赖，安装包需随附合规的 Git 工具及许可证，或在打包验证阶段明确提出替代实现；不能在干净环境验收时借用开发机已安装的 Git。外部 Claude、graphify、github-mcp-server 属相应可选功能依赖，缺失时只影响该功能并提供说明。
- 原始聊天、来源引用、设置、凭证和知识历史不能在迁移中丢失。默认创建独立桌面数据目录，不自动覆盖旧 Compose 数据；旧数据通过显式导出/导入迁移，先校验副本和引用一致性，再切换。迁移失败保留旧数据与导出，不能静默改用空库。
- 对已有配置使用显式的兼容迁移，不改变用户模型登录方式，不把密钥复制进界面、日志或构建产物。

## 本机访问边界

- 服务只绑定 loopback。桌面窗口保持 Node integration 关闭、context isolation 与 sandbox 开启，界面不直接取得模型凭证或任意进程/文件操作权限。
- 本机 API 仍需 Host、Origin 与认证保护；浏览器入口通过一次性启动票据建立受保护的会话，不把长期凭证放入 URL，不以“只监听本机”代替鉴权。
- 本机端口冲突必须连接经验证的本应用实例或报错/选择空闲端口，不连接身份不明的服务。CLI/MCP/hook 通过受保护的实例描述定位实际地址，不能只信任固定端口。
- 浏览器模式解决桌面窗口/渲染层不可用，不承诺绕过操作系统对未受信任程序的阻止；核心或存储故障时，两个入口都会受影响。

## 安装包与发布

- 初始目标：Windows x64，macOS arm64 与 x64；其余环境保留本地 Web 运行路径。Linux 桌面安装包不作为第一批发布必备产物，调整原先三平台桌面安装包验收的要求。
- 提议产物：Windows 安装程序和便携 ZIP；macOS DMG 和 ZIP；每个产物含明确版本、平台和架构。浏览器模式启动入口及所需运行时随分发产物提供。
- 不要求用户先购买证书。预发布包明确标记未进行发行者身份签名/公证，macOS 可能需按 Apple 系统设置允许打开，Windows 可能显示未知发布者或信誉提示；企业策略可能直接阻止运行，不承诺一定可以放行。后续加入证书时通过 Actions secrets 注入，不提交到仓库。
- 只有推送合法版本 tag 才进入发布工作流，例如 `v0.1.0-beta.1`；校验 tag 与应用版本一致。普通 push/PR 仅检查，不发布。带预发布后缀的 tag 发布为 GitHub prerelease，正式版本 tag 才为普通 Release。
- 每个目标在原生 GitHub runner 构建，依赖固定 lockfile，执行适用测试与打包后启动冒烟。先上传 Actions artifacts；全部目标通过后由单一发布 job 收集完整产物、SHA256 清单及发布说明，再创建/发布 Release，避免并发 job 互相覆盖或发布半套安装包。
- 发布 job 使用最小必需 `contents: write` 权限，固定到 tag 对应提交。失败的构建不对外发布完成版本；重跑不得静默覆盖既有正式产物。
- 下载入口使用现有公开仓库 `https://github.com/Nema-Project/nema-room/releases`，版本页面为 `/releases/tag/<tag>`。只有 Actions 真实发布并完成匿名下载校验后，才声称下载地址已可用。

## 验收与发布边界

1. 干净 Windows/macOS 环境安装，无 Docker、独立数据库、全局 Node/npm，基本功能可运行。
2. 桌面与浏览器入口访问同一 workspace、消息、知识与历史；窗口打不开时仍可独立启动浏览器模式。
3. 真实模型完成聊天、整理、追问与开发交接；重启恢复、中断处理、凭证保护与 Git 历史正确。
4. 验证 optional Agent/插件缺失时的降级行为，不影响不需要该依赖的基本功能。
5. tag 流水线在各目标构建并冒烟通过，发布完整产物与校验值，匿名下载有效。CI 启动冒烟不能替代带下载隔离属性的真实首次安装体验验证。

## 留给实现者

具体模块拆分、进程通信内部封装、端口分配、样式、测试组织、锁文件格式、随附工具版本与依赖打包细节由实现者决定；不能改变本机独立、同数据双入口、公开 tag 发布、凭证隔离和数据保护边界。数据库候选失败、无法提供独立浏览器启动或干净安装所需核心依赖时，必须回到设计处理，不能静默削减验收范围。
