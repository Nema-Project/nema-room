- 日期：2026-10-24（Asia/Tokyo）。
- 状态：产品方向与范围已由用户确认；技术选型和实现尚未完成。
- 取代：原设计 6.4–6.5 中将 Web / Compose 服务端视为首版交付形态、为未来服务器迁移预先拆分运行链的安排。
- 原始设计：[Nema Room 设计](2026-10-21-nema-room-design.md)。

> 后续讨论补充：用户要求保留本机 Web 入口，优先 Windows/macOS 桌面交付，以代码复用和稳定交付为选型依据；通过 tag 触发 Actions，安装包发布到已公开的 MIT 仓库。用户已确认按[桌面打包与发布设计](2026-10-24-desktop-packaging-design.md)推进，先交付未签名预发布。Linux 保留本机 Web 路径，不要求首批提供桌面安装包。

## 已确认的方向

首版是用户在自己电脑上安装并完整使用的桌面应用。聊天界面、聊天与项目知识的持久化、任务调度、模型访问和本机工具执行，都必须在本机具备。没有部署 Nema 服务器、服务器停止或服务器不可达时，基本能力仍然可用。

多设备同步、备份功能、团队只读查看，以及可能承载这些能力的可选服务器，全部等本地基本实现完成后再考虑。本阶段不为这些功能实现额外运行服务、账户系统或同步协议。保留数据和正确完成持久化是基本能力，不能因为备份功能延期而省略。

“本机独立”不代表“完全断网推理”：使用云端模型、GitHub 等外部服务仍需要相应网络连接。本机休眠或关机时不要求继续执行 Agent。

## 首版基本能力

1. 安装并启动桌面应用，完成模型与凭证配置；日常使用无需打开终端启动 daemon，无需安装 Docker 或维护独立数据库服务。
2. 在本机创建和切换 workspace、发送消息、接收流式结果、整理需求与追问，持久化聊天、设置和任务状态。
3. 保留条目的来源、依据、知识 Git 历史和修改理由。迁移不得只保存知识而丢失原始聊天及其引用关系。
4. 保留已有模型适配器、凭证保护和 Room 工具访问校验。凭证与模型请求由受信任的本机运行层处理，界面不直接获得秘密。
5. 保留已支持的本机仓库、代码上下文、开发包和上报能力。管理后台执行的生命周期，避免遗留进程或重复执行。
6. 关闭后重新打开，聊天、知识、设置和已完成任务可恢复；中途退出的任务标记为中断并允许明确重试，不得声称已经完成或静默重复写入。

## 运行边界

```text
用户电脑
  桌面界面
       ↕ 本机受控通信
  应用运行层：聊天 / 任务 / Room 校验 / 模型适配器 / 本机工具
       ↕
  本机持久化：聊天与设置数据库 + workspace 知识 Git 仓库

  应用运行层 → 用户选择的云端模型或外部插件服务（按功能需要）
```

现有 hub 和 daemon 的职责可以在迁移中复用，但进程拆分是内部实现选择。用户不承担启动两套服务、配置连接、保持单独终端运行的责任。单纯把远端网页嵌入桌面窗口不满足本设计。

## 技术选择仍需验证

- 桌面外壳、打包和更新方式尚未选定；先验证现有 React 界面与 TypeScript 执行代码的复用路径。
- 本机存储必须无需独立数据库服务。审计 PostgreSQL SQL、事务及队列语义。现有内存 PGlite 测试通过，不等于磁盘持久化、崩溃恢复和桌面打包已经验证；不能直接宣布可替代生产数据库。
- 一起设计桌面入口、CLI / MCP / hook 的生命周期与发现方式，明确关闭窗口、退出应用和外部上报时的行为。
- 沿用本机 HTTP / WebSocket 时仍需鉴权、来源限制和最小暴露；采用桌面 IPC 时仍需限制接口和输入。不得向界面内容开放任意文件访问、数据库、模型凭证或任意进程启动能力。

这些是实现调查任务，不是用户已经选定的框架、数据库或通信协议。

## 迁移与验收

顺序见[迁移计划](../plans/2026-10-24-local-desktop-migration.md)。现有 Compose / Web 代码作为迁移来源保留，旧架构测试通过不代表桌面版本已完成。

Windows、macOS、Linux 均需验证：安装启动、不启动 Docker 或独立数据库即可完成一轮真实聊天与知识更新、重启恢复、中断任务处理、凭证保护、本机仓库及上报工具可用。验收环境中不部署 Nema 服务器，应用本体不依赖开发机全局 Node/npm；可选插件或 Agent 自身的前置条件另行说明。

现有数据迁移使用副本或导出：保留旧数据库和知识仓库，校验消息、条目、来源引用及历史的一致性，成功后再切换。不得静默删除或覆盖旧数据。
