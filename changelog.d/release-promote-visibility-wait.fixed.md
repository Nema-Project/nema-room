- `release-promote` no longer gives up when the npm registry has not indexed a just-published version yet. After the publish run reports success it re-reads the exact version and the expected `latest` (or prerelease `next`) dist-tag for up to two minutes, then continues the promotion, so a maintainer no longer has to re-run the job because of registry lag (v0.2.0's first promote attempt failed that way and a rerun succeeded). A tarball with another integrity, a 401/403, or an answer that cannot be interpreted still stops immediately. When the budget runs out the run still exits non-zero without moving any later pointer, and its summary says whether the registry confirmed the version is not there or whether that could not be determined.
