- Chat messages and thread replies can carry images (PNG, JPEG, WebP, GIF), PDFs and UTF-8 text files: paste them, drop them on the composer, or pick them with the Attach button. Files are previewed and removable before sending, a message may hold only attachments, and the composer says before sending when the current adapter cannot read a type, instead of sending it to be ignored. Sent attachments appear in the message as thumbnails or file cards you can download. Deleting one removes its content from Nema and leaves a tombstone with the name, type, size, sha256 and deletion time; what an agent or model already received cannot be taken back. If removing a deleted attachment's file fails, the deletion still stands: open chats switch to the tombstone at once, the delete reports the failure, and the hourly cleanup removes the file later. The user guide lists which runtime reads which attachment type: PDFs with Claude Code, and images and PDFs with Codex login compatibility or a BYOK endpoint other than OpenAI's, are refused before the run until they have been verified. With BYOK pointed exactly at `https://openrouter.ai/api/v1`, images are now sent to the model (checked with a free vision model); PDFs there stay refused, because OpenRouter reads them through its paid OCR by default.
