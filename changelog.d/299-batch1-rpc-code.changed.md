- Daemon and hub errors can now carry an optional error code with parameters (`RpcResponse.code`, `CodedError`, `DaemonRpcError.code`, and `{ error, code, params }` HTTP bodies), and the web shows coded errors in the selected UI language. Repository binding and preview, the folder picker, the mirror address check, daemon-offline errors, and a few hub-side errors (plugin settings, attachment delivery limit, work package and implementation confirmation) are the first to use codes (#299).
- Progress lines from a running task (account switches, tool calls, and Skill loading warnings, including repository Skill warnings) now carry codes as well, so the thread shows them in the selected UI language. An account switch reuses the same route-failure wording as the message route line (#299).
- Codes are optional everywhere and the protocol version is unchanged: an older daemon or hub that sends only text, or a code the page does not know, is shown with the original text as before.
